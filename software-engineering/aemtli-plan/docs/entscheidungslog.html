Entscheidungslog

Die Entscheide E-01 bis E-17 hat Claude Code am 13.10.2026 als Vorschlag erarbeitet. Ray hat sie pauschal als Arbeitsgrundlage freigegeben, aber noch nicht einzeln geprüft. Status «vorläufig» bedeutet, dass der Entscheid noch im Team bestätigt werden muss.

ID Datum Entscheid Begründung Verworfene Alternativen Status
E-01 13.10.2026 Jede Person ist in höchstens einer WG. Entspricht der Realität, hält Bedienung und Regeln einfach und ist im Code von F1 bereits so umgesetzt. Mehrere WGs pro Person (z.B. Wochenaufenthalter) vorläufig
E-02 13.10.2026 Alle Mitglieder sehen den Einladungscode, nur Admins können ihn erneuern. So kann z.B. auch Marco neue Mitbewohnende einladen. Code nur für Admins sichtbar vorläufig
E-03 13.10.2026 Wer den Code eingibt, ist sofort Mitglied, ohne Freigabe. Ein einfacher Einstieg ist wichtig (Sara). Das Risiko mildern Code-Erneuerung und Entfernen. Freigabe jedes Beitritts durch einen Admin vorläufig
E-04 13.10.2026 Man kann die WG selbst verlassen. Der letzte Admin muss vorher die Rolle weitergeben. Verlässt die letzte Person die WG, wird diese gelöscht. Auszüge sind normal. Ohne Admin wäre eine WG nicht mehr zu verwalten. Nur Admins können Mitglieder entfernen (Stand Code) vorläufig
E-05 13.10.2026 Die Rotation läuft reihum: Jedes Ämtli geht jede Woche (Montag bis Sonntag) an die nächste Person in einer festen Reihenfolge, nämlich der Beitrittsreihenfolge. Einfach, vorhersehbar und nachweisbar fair. Zufällige Zuteilung; Zuteilung nach Punkten oder Aufwand vorläufig
E-06 13.10.2026 Neue Mitglieder werden ab der nächsten Woche eingeplant. Ausgetretene fallen ab der nächsten Woche weg, ihre offenen Ämtli der laufenden Woche entfallen. Die laufende Woche bleibt stabil, niemand erhält mitten in der Woche ein Ämtli. Sofortige Neuverteilung vorläufig
E-07 13.10.2026 Unerledigte Ämtli werden nicht nachgeholt und nicht bestraft. Sie bleiben im Verlauf sichtbar. Transparenz statt Kontrolle. Strafen machen Bedienung und Regeln komplizierter. Übertrag in die nächste Woche; Strafpunkte vorläufig
E-08 13.10.2026 Ämtli können nicht getauscht oder ausgesetzt werden. Hält den Umfang klein. Absprachen passieren im WG-Chat. Tauschfunktion; Ferienmodus vorläufig
E-09 13.10.2026 Ausgaben werden gleichmässig auf die ausgewählten Personen aufgeteilt. Deckt den Normalfall (Znacht, Putzmittel) ab und ist leicht nachvollziehbar. Individuelle Beträge; Prozente; Gewichtung vorläufig
E-10 13.10.2026 Die Anteile der anderen werden kaufmännisch auf 5 Rappen gerundet. Den Rest trägt die zahlende Person. In der Schweiz übliche Rundung, gut zu überweisen. Die Summe stimmt immer genau. Exakte Rappen; Rest an eine zufällige Person; Rest verfällt vorläufig
E-11 13.10.2026 Die zahlende Person ist immer an der Ausgabe beteiligt. Macht die Rundungsregel eindeutig und deckt den Normalfall ab. Ausgaben nur für andere, z.B. ein Geschenk vorläufig
E-12 13.10.2026 Rückzahlungen werden in der App festgehalten. Das Geld fliesst ausserhalb der App. Ohne Rückzahlungen würden die Saldi nie ausgeglichen. Eine Zahlungsabwicklung wäre zu gross und juristisch heikel. Integration von TWINT oder einer Bank; Saldo von Hand zurücksetzen vorläufig
E-13 13.10.2026 Eine Ausgabe dürfen nur die erfassende Person und Admins ändern oder löschen. Fehler bleiben korrigierbar, und es kann nicht jede Person alles ändern. Alle dürfen alles ändern; niemand darf ändern vorläufig
E-14 13.10.2026 F4: Pro WG gibt es eine Einkaufsliste. Artikel haben keine Preise, beim Umwandeln wird nur der Gesamtbetrag erfasst. Schnelle Bedienung im Laden. Es zählt der Betrag auf dem Kassenzettel. Mehrere Listen; Preis pro Artikel vorläufig
E-15 13.10.2026 Der Ausgleichsvorschlag braucht höchstens n − 1 Überweisungen: Die Person mit der grössten Schuld zahlt jeweils der Person mit dem grössten Guthaben. Einfach umzusetzen und zu erklären. Erfüllt «wer schuldet wem». Jede Ausgabe einzeln begleichen; mathematisch minimale Anzahl Überweisungen (aufwendig) vorläufig
E-16 13.10.2026 Keine Anbindung an externe Systeme wie E-Mail, Push-Nachrichten oder Zahlungsdienste. Die App muss auf einem frischen Laptop ohne Zugangsdaten laufen. Das hält den Umfang klein. E-Mail-Einladung; Erinnerungen vorläufig
E-17 13.10.2026 Die Anforderungsdoku liegt als Markdown im Repo unter docs/. Sie wird zusammen mit dem Code versioniert und ist für alle sichtbar. Word-Dokument; Wiki vorläufig
E-18 13.10.2026 Frontend mit Bootstrap 5, lokal im Projekt unter static/vendor/ (kein CDN, kein Build-Schritt). Ray kennt Bootstrap schon. Läuft offline und nach pip install ohne Node.js, also auch auf einem frischen Laptop. Bietet fertige Bausteine wie Navbar und Alerts. Tailwind (braucht Node.js für den Build oder ein CDN mit Internet); Pico.css (Empfehlung der KI, aber im Team unbekannt) bestätigt (Ray)
E-19 13.10.2026 Zuteilungen, Ausgaben, Anteile und Rückzahlungen hängen am Benutzer, nicht an der Mitgliedschaft. Die Mitgliedschaft wird beim Austritt gelöscht, Verlauf und Abrechnung sollen aber erhalten bleiben. Verknüpfung über die Mitgliedschaft; Mitgliedschaft nur als «inaktiv» markieren vorläufig
E-20 13.10.2026 Die Woche ist keine eigene Klasse, sondern eine Eigenschaft der Zuteilung. Eine Woche hat ausser ihrem Datum keine eigenen Daten. Eigene Klasse «Woche» vorläufig
E-21 13.10.2026 Saldo und Ausgleichsvorschlag werden jedes Mal berechnet, nicht gespeichert. Sie können so nie im Widerspruch zu den Buchungen stehen. Saldo als gespeicherter Wert, der bei jeder Buchung nachgeführt wird vorläufig
E-22 13.10.2026 Keine Assoziation zwischen Artikel und Ausgabe. Die Artikel werden beim Umwandeln entfernt und in die Beschreibung der Ausgabe übernommen. Einfacher, und so verlangt es US-F4-03. Artikel bleiben erhalten und verweisen auf die Ausgabe vorläufig
E-23 13.10.2026 Einkaufsliste als eigene Klasse (1:1 zur WG). Nah an der Fachsprache und später auf mehrere Listen erweiterbar. Artikel hängen direkt an der WG vorläufig
E-24 13.10.2026 Jeder Admin darf die ganze WG löschen (US-F1-08), nach einer Bestätigungsseite. Die Benutzerkonten bleiben bestehen. Von Ray gewünscht. Admins dürfen ohnehin alle Mitglieder entfernen, das Löschen gibt ihnen also keine wesentlich grösseren Rechte. Nur die gründende Person darf löschen; Zustimmung aller Mitglieder; Eingabe des WG-Namens zur Bestätigung vorläufig
E-25 10.11.2026 Admins können ein offenes Ämtli der laufenden Woche einer anderen Person geben (US-F2-06). Die Rotation der folgenden Wochen ändert sich dadurch nicht. Schwächt E-08 ab. Von Ray gewünscht. Deckt Ferien, Krankheit und entfallene Ämtli ab, ohne die Fairness der Rotation zu gefährden.
